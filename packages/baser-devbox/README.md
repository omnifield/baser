# `@omnifield/baser-devbox` — обвес девбокса

**Проект целиком в контейнере: `.devcontainer` как шаблон с пресетом.** Первый
настоящий обвес baser — тот, на котором станок впервые что-то положил в живой
репозиторий (`tasker:BASER2-18`, `tasker:BASER2-21`).

Пакет **не содержит кода**: объявление в `package.json`, содержимое в
`template/`, вычисляемые дефолты в `defaults.mjs`. Ни точки входа, ни сборки, ни
`dist` — обвес это инструмент в патроне, а не ещё один мотор (`kb:BASER2-4`).

```
package.json     блок `baser` — объявление обвеса по форме хвостовика
defaults.mjs     резолверы: имя девбокса, алиас в сети, пин версии Node
template/        devcontainer.json.ejs · devcontainer-lock.json
```

## Как им пользуются

```jsonc
// baser.json в корне репозитория
{
  "sources": [{ "use": "@omnifield/baser-devbox", "presets": ["omnifield"] }],
}
```

```
pnpm add -D @omnifield/baser-devbox
npx baser apply
```

**Вопросов не будет ни одного.** Имя девбокса считается из имени репозитория,
всё остальное — дефолты и пресет (`tasker:BASER2-18`). Кладётся два файла:
`.devcontainer/devcontainer.json` и `.devcontainer/devcontainer-lock.json`.

Внешнему пользователю пресет `omnifield` не нужен — без него обвес даёт валидный
самостоятельный девбокс.

## Три слоя, и они не смешиваются

| слой              | что в нём                                                                                                                    | чем выражен                     |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------- | ------------------------------- |
| **универсальное** | всё в контейнере · рабочая папка в томе · креды и кэши в отдельных томах · `host.docker.internal` · рестарт с демоном        | тело шаблона, без ветвлений     |
| **настройки**     | имя девбокса · образ и версия рантайма · команда установки зависимостей · расширения и форматтер редактора · приватный scope | `settings` + подстановка        |
| **пресет**        | сеть `omnifield-gateway` · peer-alias · ноль host-портов · общие тома · ассистент внутри                                     | `presets.omnifield` + ветвление |

**Пресет, а не второй обвес.** Два источника не могут делить один файл
(`kb:BASER2-6`): «базовый + надстройка omnifield» выражается ИМЕНОВАННЫМ НАБОРОМ
ЗНАЧЕНИЙ внутри одного обвеса, а не вторым источником поверх первого. Отсюда же
требование к языку шаблона: без ветвления третий слой невыразим, поэтому форма
даёт `<% if %>`, а не только подстановку.

Слои не смешиваются проверяемо: `test/layers.spec.mjs` раскладывает обвес трижды
— без пресета, с пресетом и с заполненными значениями — и отдельно проверяет,
что универсальное переживает СНЯТИЕ пресета. Слой, который держится только
пресетом, универсальным не является.

## Настройки

| ключ               | тип       | дефолт                                                       |
| ------------------ | --------- | ------------------------------------------------------------ |
| `name`             | `string`  | `<репозиторий>-devbox` (вычисляемый)                         |
| `image`            | `string`  | `mcr.microsoft.com/devcontainers/typescript-node`            |
| `runtimeVersion`   | `string`  | `24` (вычисляемый — пин выпуска, см. ниже)                   |
| `installCommand`   | `string`  | `pnpm install --frozen-lockfile`                             |
| `editorExtensions` | `list`    | `esbenp.prettier-vscode`, `nrwl.angular-console`             |
| `editorFormatter`  | `string`  | `esbenp.prettier-vscode` — попадает в `editorExtensions` сам |
| `privateScope`     | `string`  | `null` — проверки доступа к реестру нет                      |
| `network`          | `string`  | `null` — пресет ставит `omnifield-gateway`                   |
| `networkAlias`     | `string`  | `<репозиторий>` (вычисляемый)                                |
| `secretsVolume`    | `string`  | `null` — пресет ставит `omnifield-secrets`                   |
| `pnpmStoreVolume`  | `string`  | `null` — пресет ставит `omnifield-pnpm-store`                |
| `installAssistant` | `boolean` | `false` — пресет ставит `true`                               |

Не заполнил — идёшь за нашим выпуском. Заполнил — не поднимется никогда: движок
в конфиг пользователя не пишет, подниматься физически неоткуда (`kb:BASER2-5`).

## Где проходит граница слота (решения выпуска 0.2.0)

Обе настройки выше появились не по симметрии, а по прогону на **weber** — втором
потребителе, чужом и настоящем. Отсутствие слота под ходовую нужду — НАШ брак, а
не выбор пользователя (`kb:BASER2-7`), поэтому важно, где эта граница проходит.

### Форматтер — да. Сквозной проброс настроек редактора — нет

weber на biome, а в шаблоне стоял прибитый гвоздями `esbenp.prettier-vscode`.
Единственный ход потребителя — править артефакт руками, то есть форкать обвес
целиком из-за одной строки. Это дефект шаблона (`kb:BASER2-2` §5).

Слот заводится, когда значение **диктует стек репозитория** и без слота артефакт
приезжает заведомо неверным: контейнер, куда поставили biome и прописали
форматтером prettier, сломан при рождении. Слот НЕ заводится под вкус
разработчика — вкусу есть легальный путь, не требующий форка: `.vscode/settings.json`
самого репозитория, которого наш артефакт не касается.

Поэтому `editor.formatOnSave` слотом не стал (вкус), а `typescript.tsdk` — не стал
тем более: он указывает на TypeScript самого репозитория, и для образа
`typescript-node` другого верного значения нет.

#### Форматтер и список расширений — одно утверждение, и обвес держит его сам

`editor.defaultFormatter` принимает **идентификатор расширения**, поставляющего
форматтер. Значит «форматтер задан» и «расширение стоит» — не две настройки, которые
обязаны совпасть, а одно и то же утверждение. Поэтому заданный `editorFormatter`
обвес **сам добавляет в `editorExtensions`**, если его там нет.

Отказ («форматтер не среди расширений») был бы хуже: он требует действия от человека
там, где верный ответ обвесу известен. Так класс ошибки — форматтер, которого в
контейнере нет, — исчезает, а не ловится.

Правило видно в артефакте (расширение в списке + комментарий на месте), названо в
описании настройки и закрыто тестом: форматтер вне списка → список, где он есть.

**Исключение — встроенные расширения.** Издатель `vscode.` зарезервирован за теми,
что уже в редакторе (`vscode.json-language-features` и прочие); из маркетплейса их
не ставят, и запись о них в `extensions` — несуществующий идентификатор в артефакте,
то есть та же тихая неверность с другой стороны. Правило сужено, а не отменено:
чинить по построению — значит не чинить одно, ломая соседнее.

Сквозного проброса произвольных настроек редактора не будет. Он и невыразим
формой — вложенных типов у настроек нет намеренно, иначе настройка превращается
обратно в разметку файла, — и обессмысливает обвес: пробрасывающий что угодно не
обещает ничего. Набор ключей в `customizations.vscode.settings` закрыт, и это
проверяется тестом, а не декларируется.

### Приватный реестр — настройка, и НЕ часть пресета

Старый девбокс weber перед установкой проверял доступ к GitHub Packages и говорил
человеку, куда идти за кредами. При переезде на обвес проверка пропала: без неё
npm уходит в npmjs.org и отвечает «404, пакета нет» — и человек идёт искать
несуществующий пакет вместо своих кредов. Стена без указателя.

`privateScope` — настройка с дефолтом `null`: **внешнему потребителю приватный
реестр не нужен вообще**, и без scope в артефакте нет ни строки про реестр.

В пресет `omnifield` она НЕ уехала, и это отдельное решение. Пресет — ходовое
положение регулировок для раскладки omnifield, а зависимость от приватного реестра
— свойство КОНКРЕТНОГО репозитория: weber свои `@omnifield/*` потребляет, baser их
производит и ставит воркспейс-ссылками. Включи проверку пресетом — и наш
собственный девбокс падал бы на постсоздании, требуя кредов, которые ему не нужны.
Пресет, ломающий своего же потребителя, — не пресет.

Проверка стоит **перед** установкой (иначе она рассказывает про уже случившийся
невнятный отказ) и **после** `chown` на том с кредами (иначе читает файл, права на
который ещё не выставлены). Оба порядка держатся тестом, а не комментарием.

## Версия рантайма: почему `24` и откуда это число

**Это решение выпуска, а не константа.** Резолвер обязан быть синхронной чистой
функцией без сети (`packages/baser-contracts/README.md` §3), поэтому «последняя
стабильная» не может вычисляться в момент установки — за ней пришлось бы идти в
реестр, а дефолт, ездящий по календарю, ломает воспроизводимость коммита.
Значит версия **пинится при выпуске обвеса** и двигается вместе с его версией:
видно в диффе, видно в ревью, одинаково на любой машине и в оффлайне.

Пин на сегодня — **Node 24**, и оснований два, оба проверяемых:

1. **Node 24 «Krypton» — Active LTS на дату выпуска** (2026-07-27). По графику
   релизов Node.js: 24 в Active LTS с 2025-10-28 по 2026-10-20. Линия 22 ушла в
   maintenance 2025-10-21 — выпускать сегодня обвес с дефолтом на
   maintenance-линии значило бы отдавать новому потребителю заведомо стареющий
   рантайм. Линия 26 вышла в апреле 2026, но Active LTS станет только
   2026-10-20: «последняя стабильная» — это LTS, а не Current.
2. **Тег реально опубликован семейством образа.** У
   `mcr.microsoft.com/devcontainers/typescript-node` на 2026-07-27 есть теги
   `18`/`20`/`22`/`24` и НЕТ `26` — семейство само идёт за LTS. Дефолт,
   указывающий на несуществующий тег, — сломанный девбокс, а не смелый.

**Когда двигать:** следующая чётная линия входит в Active LTS (ближайшая точка —
2026-10-20, Node 26) И семейство образа опубликовало соответствующий тег.
Движение дверь назовёт потребителю до применения («подниму версию с 24 на 26») —
спрашивать она не будет и не должна.

Обоснование живёт в `defaults.mjs` рядом с той строкой, которую придётся
переписать, а число зафиксировано тестом: молча двинуть его правкой одной строки
нельзя.

## Версия обвеса: почему `0.2.0`, а не `0.1.1` и не `1.0.0`

Выпуск добавил две настройки (`editorFormatter`, `privateScope`) и не тронул ни
одной существующей. Отсюда все три границы:

- **не patch** — появилась новая поверхность, а не починка старой. Потребитель
  получает то, чего у него не было, и об этом обязано быть видно по номеру;
- **не major** — ломать нечего: ни одна настройка не переименована и не удалена,
  выпущенные `baser.json` остаются валидными как есть, править потребителю нечего;
- **minor** — ровно этот случай. Заодно номер сходится с тем, что посчитал бы
  `nx release` по conventional commits (`feat` → minor): версия и коммит не
  расходятся, а значит одну из них не придётся объяснять.

**Что увидит потребитель, стоявший на `0.1.0`.** Апгрейд перекладывает артефакт —
дверь назовёт шаг `diverged`. Меняются ДВЕ строки, и обе комментарии: ярлык про
редактор (перестал утверждать «НЕ biome» — форматтер стал настройкой) и
перечисление шагов постсоздания. **Ни одной строки данных не меняется** — это не
обещание в доке, а отдельный тест приёмки.

## Приёмка

**Зелёные тесты закрытием не являются.** Приёмка этой зоны — утверждение, а не
прогон: _обвес, поставленный КАК ПАКЕТ, раскладывается дверью в чистое дерево — и
под наш стек, и под стек weber, — а на наших настройках результат совпадает с
живым `.devcontainer` этого репозитория с точностью до настроек._

**Потребителей два, и это условие пригодности, а не полнота покрытия.** Обвес,
проверенный на единственном репозитории, доказывает совместимость с самим собой:
ровно так прибитый гвоздями форматтер прожил до weber. Второй профиль — biome + Nx,
приватный реестр, установка без `--frozen-lockfile`.

```
npx vitest run --config packages/baser-devbox/vitest.config.mts
```

| файл                   | что доказывает                                                                             |
| ---------------------- | ------------------------------------------------------------------------------------------ |
| `acceptance.spec.mjs`  | приёмка целиком: тарбол → `node_modules` → дверь → диск → сверка с живым файлом; оба стека |
| `declaration.spec.mjs` | обвес объявляет ровно то, что реально уехало в тарболе                                     |
| `layers.spec.mjs`      | три слоя выражены и не смешиваются; граница слота закрыта                                  |
| `registry.spec.mjs`    | проверка доступа к реестру ИСПОЛНЯЕТСЯ — оба отказа, успех и путь восстановления           |
| `defaults.spec.mjs`    | резолверы синхронны, чисты, без сети; пин конкретный, а не `latest`                        |

Всё меряется по **распакованному `npm pack`**, а не по каталогу монорепы
(`test/packed.mjs`). Это ровно та проверка, которой у примера внутри чужого
пакета быть не могло: пока обвес жил каталогом, «объявил» и «лежит» были одним и
тем же фактом. Как только он стал пакетом, между ними встал `files` — и они
получили право разойтись молча:

| что не уехало    | как ломается у потребителя                    |
| ---------------- | --------------------------------------------- |
| `contentRoot`    | движок не находит источник: `missing-source`  |
| один `src`       | тот же отказ, но на одном артефакте из двух   |
| `defaultFrom`    | `resolver-failed` при первом же прогоне двери |
| `./package.json` | дверь вообще не находит пакет: `not-found`    |

### Мутации: соврал в настройке — падает

Проверка, которую нельзя провалить, ничего не проверяет. Числа сняты на дереве,
где все 59 зелёные:

| мутация                                            | падает тестов                  |
| -------------------------------------------------- | ------------------------------ |
| `defaults.mjs` убран из `files`                    | 38 (+12 не доходят до прогона) |
| соврать в `contentRoot`                            | 43                             |
| проверка реестра встала ПОСЛЕ установки            | 7                              |
| проверки реестра нет вовсе                         | 7                              |
| `privateScope` уехал в пресет `omnifield`          | 5                              |
| дефолт форматтера соврал (`biome` вместо prettier) | 3                              |
| форматтер снова прибит гвоздями в шаблоне          | 2                              |
| дубль форматтера в списке не отсекается            | 6                              |
| форматтер не добавляется в список расширений       | 1                              |
| исключение для встроенных расширений снято         | 1                              |
| обещание в сообщении соврало (`--location=global`) | 1                              |

Последняя мутация нашла дефект в самой пробе, а не в обвесе: тест исполняет
команды, ВЗЯТЫЕ ИЗ СООБЩЕНИЯ, — и испорченное сообщение записало приватный реестр
в общий `npmrc` машины, отравив последующие прогоны. Клетку пришлось ставить
дважды: `NPM_CONFIG_GLOBALCONFIG` не держал (путь npm выводит из `prefix`), а
`NPM_CONFIG_PREFIX` перебивался унаследованным от `npx` `npm_config_prefix` в
нижнем регистре. Держит очистка всех `npm_config_*` из окружения — она же вернее
по сути: постсоздание выполняется в контейнере, а не из-под npx.

Урок шире npm: **проба, исполняющая то, что ей продиктовали, обязана быть
герметичной независимо от продиктованного.**

### Расхождения с живым файлом — названы поимённо

Приёмка не сверяет «примерно»: она считает список различающихся строк и проверяет
его ЦЕЛИКОМ. Инвариант, который держит «до настроек» честным: **расходятся только
значения настроек и комментарии, эти значения описывающие. Ни одной строки
данных** — и это отдельный тест, а не наблюдение.

| строка                          | почему                                                                                                                                                         |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 2 — комментарий-заголовок       | в живом файле руками написано «baser devbox», обвес подставляет `name` → «baser-devbox». Прозаическое, не структурное; то же расхождение назвала проба формы   |
| 8 — `"image"`                   | живой репозиторий стоит на Node 22, дефолт выпуска — 24. Это и есть «до настроек»: заполни `runtimeVersion: "22"` — расхождение исчезает, и это отдельный тест |
| 47 — комментарий о редакторе    | в живом файле «baser-стек = prettier + Nx (НЕ biome)» — утверждение о стеке ПОТРЕБИТЕЛЯ, которое врёт всякому, у кого стек другой (0.2.0)                      |
| 61 — комментарий о постсоздании | перечисляет шаги и потому собирается из тех же частей, что и сами шаги; «install по lock» соврал бы weber, у которого установка без lock (0.2.0)               |

Структурных расхождений нет: остальные строки сверяются точно.

## Чего в пакете намеренно нет

- **Сборки и `dist`.** `defaultFrom` дверь резолвит путём внутри распакованного
  пакета, а не через `exports`: «собранный dist» означал бы, что обвес не
  работает до сборки — то есть не работает у потребителя.
- **Точки входа `.`.** Импортировать здесь нечего. `exports` называет ровно два
  адреса: `./package.json` (по нему дверь находит пакет) и `./defaults.mjs` (его
  зовёт она же).
- **Зависимостей.** Ни на дверь, ни на форму: обвес — контент. Прогон приёмки
  зовёт дверь из монорепы напрямую по пути, а у потребителя дверь стоит своим
  пакетом рядом.
- **Второго обвеса на тот же файл.** См. `kb:BASER2-6`.

## Известные шероховатости

- **Универсальный слой цитирует внутреннюю KB.** В шапке артефакта стоят
  `kb:ADR-16`, `kb:FUND-4`, `kb:ADR-20` — для внешнего пользователя это шум.
  Убрать их сейчас значило бы разойтись с живым `.devcontainer`, то есть с
  эталоном приёмки; правится вместе с ним, отдельным решением.
- **Копия обвеса в `packages/baser-contracts/examples/devbox`.** Проба формы и
  приёмка двери всё ещё гоняются по ней, а не по этому пакету. Копии разъехались
  уже на версии Node (пример: 22, пакет: 24), а с `0.2.0` — ещё и на двух
  настройках. Разводится задачами `tasker:BASER2-26` и `tasker:BASER2-27`.
- **Связь `editorFormatter` ↔ `editorExtensions` закрыта по построению, а не
  проверкой** (решение architect, `tasker:BASER2-22`). Механизм «связанных
  настроек» в форму не заводили: он строился бы на единственном примере, а форма
  растёт дороже, чем чинится случай. Если появится вторая пара настроек, которые
  обязаны совпадать и НЕ выражают одно утверждение, — вопрос вернётся к форме.
