# `@omnifield/baser-git` — обвес git-обвязки

**Обвязка репозитория перестаёт быть свойством НАШЕГО репозитория и становится
поставкой, которую локация добавляет командой** (`tasker:BASER2-208`). Обвес
везёт гейт заголовка PR (правило и поток, который его зовёт) и машинный
`pre-commit` — тот самый, которого не было ни в одном свежем клоне
(`tasker:BASER2-195`).

Пакет **не собирается**: объявление в `package.json`, содержимое в `template/`.
Ни точки входа, ни `dist` — обвес это инструмент на посадочном месте, а не ещё
один мотор. Единственный код здесь — резолвер предупреждения (`warning.mjs`,
форма 7): он ничего не кладёт и никуда не пишет, а отвечает на один вопрос про
локацию, в которую обвес применяют (ниже).

```
package.json     блок `baser` — объявление обвеса по форме хвостовика
template/        pr-title.mjs.ejs · pr-title.yml.ejs · pre-commit.ejs
warning.mjs      слово обвеса про эту локацию: сработает ли положенный хук
```

## Как им пользуются

```jsonc
// baser.json в корне репозитория — перечень поставленного, ни одного значения
{
  "formVersion": 5,
  "sources": [{ "use": "@omnifield/baser-git" }],
}
```

```sh
npx baser apply
```

Кладётся три файла: `.github/scripts/pr-title.mjs` (правило),
`.github/workflows/pr-title.yml` (поток, который его зовёт) и
`.git/hooks/pre-commit` (машинный гейт каденса). Все — `regenerated`: они
принадлежат поставке целиком, и правка руками не переживёт следующее применение.
Настраивается это файлом настроек `.omnifield/omnifield-git.yaml`, который дверь
рождает сама:

```yaml
baser:
  settings:
    # команда готовности, которую гоняет хук перед коммитом
    verifyCommand: 'make check'
    # перечень зон локации: заполнен — чужая зона в заголовке краснеет,
    # пуст (дефолт) — годится любая по форме
    titleScopes:
      - cli
      - engine
```

**Ничего заполнять не обязано.** На дефолтах обвес даёт рабочий гейт: типы
Conventional Commits, обязательная зона, открытый перечень зон и `pnpm verify`
перед коммитом.

## Хук ложится в `.git/hooks/` — и что из этого следует

`.git/hooks/` — папка, в которую git смотрит САМ, без единой настройки. Отсюда
две вещи, которые надо знать до установки, а не после:

- **файл не версионируется.** В свежий клон он приезжает не с `git clone`, а с
  применением обвеса. Ровно этим применение и занимается, но клон, где его не
  запускали, машины не имеет;
- **у локации с заданным `core.hooksPath` хук НЕ ЗАПУСТИТСЯ.** git в этом случае
  смотрит только в названную папку, и положенный файл остаётся лежать мёртвым.
  Так устроены husky (`core.hooksPath=.husky/_`) и всё, что ставится по его
  образцу.

Второе — **и обвес об этом ГОВОРИТ** (`tasker:BASER2-235`). Заявку на канал
подняла эта зона по этому самому случаю (`tasker:BASER2-208`): громкость у обвеса
была ровно одна — бросок резолвера, валящий весь прогон локации у всех обвесов
сразу, — то есть выбор между «промолчать» и «сломать всё». Форма 7 завела вторую
(`warningFrom`), и обвес ею пользуется:

```
остаётся человеку — консоль этого не делает и делать не начнёт:
  говорит САМ обвес "omnifield/git" — про своё применение в этой локации. Прогон при
  этом верный: предупреждение не отказ и кода возврата не меняет. Слово его, дословно:
    хук лёг в ".git/hooks/pre-commit", но git этой локации туда не смотрит:
    у неё задан core.hooksPath = ".githooks" (написано в ".git/config"),
    и запускается только то, что лежит ТАМ. Положенный файл останется мёртвым —
    эту проверку git не позовёт ни на одном коммите и не скажет об этом ни слова.

    Сними настройку там, где она написана ("git config --unset-all core.hooksPath"
    правит конфиг локации, а не глобальный), либо не рассчитывай на машинный хук
    отсюда: укладка верная — расходятся адреса, а не содержимое, и чинить в
    обвесе нечего.
```

**Прогон при этом успешен, код возврата 0, артефакты лежат.** Обвес не отказывает
и настройку не трогает: `.git/` — территория потребителя, а отказ уронил бы
применение ВСЕХ обвесов локации ради одного файла. Условие и текст объявляет
обвес (`warning.mjs`), печатает консоль: про `core.hooksPath` она не знает и
знать не должна.

Четыре решения резолвера, которые видны только изнутри:

- **спрашивает САМ git**, а не читает `.git/config`. Настройка бывает глобальной,
  системной и приехавшей через `include` — во всех трёх случаях git её слушается,
  а свой разбор INI увидел бы только первую и в остальных **промолчал бы**. Это
  ровно то молчание, против которого поле и заведено;
- **чистит окружение** (`GIT_*` снимаются целиком): `GIT_DIR` переопределяет
  поиск репозитория, и `git -C <локация>` ответил бы про ЧУЖОЙ. Случай наш
  собственный — положенный хук гоняет команду готовности с выставленным
  `GIT_DIR`;
- **сравнивает каталоги, а не строки:** настройка, указывающая туда же, куда мы
  кладём (`.git/hooks` явно, абсолютным путём, через тильду), ничего не ломает —
  и слышно про неё ничего не будет;
- **молчит вместо падения.** Нет git, нет настройки, `.git` не репозиторий, git
  не установлен — нормальные состояния обстановки. Молчание выражается пустотой:
  пустая строка от исправной работы неотличима.

**Сверка с рынком (2026-08-07).** `pre-commit` спрашивает git тем же вопросом
(`git config core.hooksPath`, пусто = не задано) и, увидев настройку, **отменяет
установку**: «Cowardly refusing to install hooks with `core.hooksPath` set»
([#1298](https://github.com/pre-commit/pre-commit/issues/1298); живой случай с
глобальной настройкой — [#1198](https://github.com/pre-commit/pre-commit/issues/1198));
`lefthook` обсуждает снятие настройки за человека
([#1248](https://github.com/evilmartians/lefthook/issues/1248)). Мы не делаем ни
того, ни другого: применение идёт по всем обвесам локации сразу, и отказ одного
гасит остальные, а чужую настройку снимать нас не просили. Вопрос к git'у берём у
них — он там же и по той же причине.

Бит исполнения объявлен раскладкой (`executable: true`, форма 6) и держится
паспортом укладки: сбитый снаружи, он возвращается применением
(`kb:BASER3-36`) — файл без `+x` git игнорирует молча, и это ровно тот класс
молчания, который обвес и убирает.

## Что обвес НЕ везёт — и почему это ответ, а не пробел

Разница между поставкой и копией нашего репозитория проходит ровно здесь.
Разметка сделана по факту (`tasker:BASER2-208`, комментарий 2026-08-07):

| наше                                        | едет | почему                                                                                 |
| ------------------------------------------- | ---- | -------------------------------------------------------------------------------------- |
| правило заголовка + его поток               | да   | zero-deps, ничего не знает ни про реестр, ни про менеджер пакетов                        |
| приёмка (`ci.yml`)                          | нет  | её каркас общий на вид, но живёт он приватным scope, токеном реестра и джобом гейта номеров, зовущим путь в нашей монорепе. Положить её `regenerated` значило бы затереть приёмку, которая у потребителя уже есть |
| выпуск и дев-выпуск                         | нет  | знают наш реестр, наши пакеты, `nx release`, `workspace:*` и нашу схему тегов            |
| пробы правил (`.github/scripts/*.spec.mjs`) | нет  | потребитель получает содержимое, а не наш способ его проверять: правило пробуется здесь, в пакете |

Машинный `pre-commit` в этой таблице больше не стоит: он **едет**. Разрыв,
который его держал, — форма объявления не выражала бит исполнения — закрыт
формой 6 (`layout[].executable`, `kb:BASER3-36`).

## Как проверено

Пробы зоны берут обвес **из тарбола** (`npm pack`), зовут **настоящую дверь** и
судят **положенный файл**:

- `acceptance.spec.mjs` — артефакты совпадают с живой обвязкой ЭТОГО
  репозитория строка в строку; повторное применение не пишет ничего;
- `hook.spec.mjs` — хук судится **попыткой коммита** в настоящем `git init`, а
  не наличием файла: на красном дереве коммит отвергнут, на зелёном проходит,
  сбитый снаружи бит возвращается применением и машина оживает. Живого эталона
  у хука нет и быть не может — `.git/` не версионируется, — поэтому эталоном
  служит вердикт git'а;
- `rule.spec.mjs` — правило судит заголовки, и каждая настройка проверена
  заголовком, чей вердикт от неё зависит;
- `declaration.spec.mjs` — объявление разбирается настоящим разбором контрактов,
  объявленные источники и резолвер лежат в тарболе, а каждая настройка описана
  так, чтобы её мог показать интерфейс, ничего не знающий про этот обвес
  (`kb:BASER3-34`);
- `warning.spec.mjs` — слово обвеса судится **живым случаем**: настоящий
  `git config core.hooksPath`, дверь зовётся argv-поверхностью (то есть с
  текстом для глаз и кодом для конвейера), а главное утверждение — что слово
  **не врёт**: в той же локации красное дерево проезжает коммитом, потому что
  положенный хук мёртв.

Живая обвязка этого репозитория — эталон приёмки, поэтому оба её файла названы
входами задачи `test` в манифесте зоны: без этого nx отдавал бы зелёное из кэша,
снятого до правки эталона.

**Слово обвеса проверено мутациями, и все четыре кусаются** (2026-08-07):
снятое поле `warningFrom` — **8 проб**; вопрос к git'у, заменённый разбором
`.git/config`, — **1** (настройка через `include`); окружение без чистки — **2**
(чужой `GIT_DIR` и туда, и обратно); снятое сравнение каталогов — **2**
(настройка, указывающая туда же, куда кладём).
