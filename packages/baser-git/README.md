# `@omnifield/baser-git` — обвес git-обвязки

**Обвязка репозитория перестаёт быть свойством НАШЕГО репозитория и становится
поставкой, которую локация добавляет командой** (`tasker:BASER2-208`). Обвес
везёт гейт заголовка PR (правило и поток, который его зовёт) и машинный
`pre-commit` — тот самый, которого не было ни в одном свежем клоне
(`tasker:BASER2-195`).

Пакет **не содержит кода**: объявление в `package.json`, содержимое в
`template/`. Ни точки входа, ни сборки, ни `dist` — обвес это инструмент на
посадочном месте, а не ещё один мотор.

```
package.json     блок `baser` — объявление обвеса по форме хвостовика
template/        pr-title.mjs.ejs · pr-title.yml.ejs · pre-commit.ejs
```

## Как им пользуются

```jsonc
// baser.json в корне репозитория — перечень поставленного, ни одного значения
{
  "formVersion": 5,
  "sources": [{ "use": "@omnifield/baser-git" }],
}
```

```sh
npx baser apply
```

Кладётся три файла: `.github/scripts/pr-title.mjs` (правило),
`.github/workflows/pr-title.yml` (поток, который его зовёт) и
`.git/hooks/pre-commit` (машинный гейт каденса). Все — `regenerated`: они
принадлежат поставке целиком, и правка руками не переживёт следующее применение.
Настраивается это файлом настроек `.omnifield/omnifield-git.yaml`, который дверь
рождает сама:

```yaml
baser:
  settings:
    # команда готовности, которую гоняет хук перед коммитом
    verifyCommand: 'make check'
    # перечень зон локации: заполнен — чужая зона в заголовке краснеет,
    # пуст (дефолт) — годится любая по форме
    titleScopes:
      - cli
      - engine
```

**Ничего заполнять не обязано.** На дефолтах обвес даёт рабочий гейт: типы
Conventional Commits, обязательная зона, открытый перечень зон и `pnpm verify`
перед коммитом.

## Хук ложится в `.git/hooks/` — и что из этого следует

`.git/hooks/` — папка, в которую git смотрит САМ, без единой настройки. Отсюда
две вещи, которые надо знать до установки, а не после:

- **файл не версионируется.** В свежий клон он приезжает не с `git clone`, а с
  применением обвеса. Ровно этим применение и занимается, но клон, где его не
  запускали, машины не имеет;
- **у локации с заданным `core.hooksPath` хук НЕ ЗАПУСТИТСЯ.** git в этом случае
  смотрит только в названную папку, и положенный файл остаётся лежать мёртвым.
  Так устроены husky (`core.hooksPath=.husky/_`) и всё, что ставится по его
  образцу.

Второе — **названный разрыв, а не свойство**: обвес обязан говорить об этом
инструментом в момент применения, а сегодня ему нечем — канал «сказать, не
отказывая» у обвеса отсутствует, а единственный доступный (бросок из резолвера)
отказывает весь прогон локации, у всех обвесов сразу. Заявка на канал — в
`tasker:BASER2-208`; до её закрытия локация с `core.hooksPath` снимает настройку
(`git config --unset core.hooksPath`) либо не рассчитывает на этот артефакт.

Бит исполнения объявлен раскладкой (`executable: true`, форма 6) и держится
паспортом укладки: сбитый снаружи, он возвращается применением
(`kb:BASER3-36`) — файл без `+x` git игнорирует молча, и это ровно тот класс
молчания, который обвес и убирает.

## Что обвес НЕ везёт — и почему это ответ, а не пробел

Разница между поставкой и копией нашего репозитория проходит ровно здесь.
Разметка сделана по факту (`tasker:BASER2-208`, комментарий 2026-08-07):

| наше                                        | едет | почему                                                                                 |
| ------------------------------------------- | ---- | -------------------------------------------------------------------------------------- |
| правило заголовка + его поток               | да   | zero-deps, ничего не знает ни про реестр, ни про менеджер пакетов                        |
| приёмка (`ci.yml`)                          | нет  | её каркас общий на вид, но живёт он приватным scope, токеном реестра и джобом гейта номеров, зовущим путь в нашей монорепе. Положить её `regenerated` значило бы затереть приёмку, которая у потребителя уже есть |
| выпуск и дев-выпуск                         | нет  | знают наш реестр, наши пакеты, `nx release`, `workspace:*` и нашу схему тегов            |
| пробы правил (`.github/scripts/*.spec.mjs`) | нет  | потребитель получает содержимое, а не наш способ его проверять: правило пробуется здесь, в пакете |

Машинный `pre-commit` в этой таблице больше не стоит: он **едет**. Разрыв,
который его держал, — форма объявления не выражала бит исполнения — закрыт
формой 6 (`layout[].executable`, `kb:BASER3-36`).

## Как проверено

Пробы зоны берут обвес **из тарбола** (`npm pack`), зовут **настоящую дверь** и
судят **положенный файл**:

- `acceptance.spec.mjs` — артефакты совпадают с живой обвязкой ЭТОГО
  репозитория строка в строку; повторное применение не пишет ничего;
- `hook.spec.mjs` — хук судится **попыткой коммита** в настоящем `git init`, а
  не наличием файла: на красном дереве коммит отвергнут, на зелёном проходит,
  сбитый снаружи бит возвращается применением и машина оживает. Живого эталона
  у хука нет и быть не может — `.git/` не версионируется, — поэтому эталоном
  служит вердикт git'а;
- `rule.spec.mjs` — правило судит заголовки, и каждая настройка проверена
  заголовком, чей вердикт от неё зависит;
- `declaration.spec.mjs` — объявление разбирается настоящим разбором контрактов,
  объявленные источники лежат в тарболе, а каждая настройка описана так, чтобы
  её мог показать интерфейс, ничего не знающий про этот обвес (`kb:BASER3-34`).

Живая обвязка этого репозитория — эталон приёмки, поэтому оба её файла названы
входами задачи `test` в манифесте зоны: без этого nx отдавал бы зелёное из кэша,
снятого до правки эталона.
